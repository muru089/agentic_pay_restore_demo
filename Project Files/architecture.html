1 · Full Agent Architecture

3-tier structure: Uber (root_agent) owns auth, safety, routing, and restore sequencing via Approach B (transcript-driven signals — no persistent state). Supervisor (SA1_DiagnosticSupervisor) handles ambiguous multi-dimensional health complaints by fanning out DA1, DA5_StorageAgent, and DA6_IntegrationAgent in parallel, then synthesising urgency to surface the highest-impact finding. Single-intent diagnostic queries (storage only / integration only) bypass SA1 and route directly from root. Domain / Squad agents own tool execution and enforce their own prerequisite gates. DA4 is shared — called by root_agent for both active-account plan changes and post-restore upgrades. DA1 is also shared — called by root_agent (SIGNAL A restore path) and by SA1 (diagnostic fan-out).

2 · Safety Pre-flight (before_agent_callback)

Fires synchronously on every turn before the root_agent LLM is invoked. Three layers in series: regex → Azure Prompt Shield → Azure Text Analyze. Any block short-circuits the chain and returns a canned response directly — the LLM never sees the message. All layers fail-open: Azure errors never block a legitimate customer. Blocks and API errors are logged to pay_restore.log.

3 · RAG Knowledge Base

Two separate pipelines: an offline indexing job (rag_seed.py) and an online retrieval tool (T10_SearchKnowledge). The indexing job is re-run whenever the HTML help center pages are updated — in production this would be a nightly scheduled job. T10 is called by root_agent for any general policy or FAQ question that doesn't require account lookup.

4 · root_agent — Restore Sequencing (Approach B)

root_agent has no persistent session state. On every turn it reads the full conversation transcript and self-determines which step to fire next via HANDOFF SIGNALS (priority order: P → D → E → C → B → A). Exactly one signal fires per turn — never two. Each domain agent enforces its own prerequisite gate and returns a structured result; root_agent relays to the customer and advances to the next signal on the following turn.

5 · SA1_DiagnosticSupervisor — Parallel Fan-out & Synthesis

Invoked by root_agent when a customer's complaint is ambiguous — symptoms that could be caused by storage, an integration failure, or an account issue. SA1 fans out all three domain agents in parallel in a single LLM turn, collects their results, and synthesises a ranked finding. Single-intent queries bypass SA1 entirely and route directly to the relevant domain agent. Two demo accounts: 20012 Taylor (Team plan, 95/100 GB — storage is the culprit) and 20013 Blake (Business plan, GitHub auth_failure — integration is the culprit).
